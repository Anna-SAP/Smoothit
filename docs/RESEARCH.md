# 研究：业余自拍与影楼人像的差距在哪里，哪些能由 App 自动弥补

> 这份文档回答三个问题：手机拍照的底层链路是什么；业余自拍和影楼级人像的差距具体出在哪些环节；
> 其中哪些可以在“按下快门的那一刻”由软件自动补上，哪些不能。Smoothit 的技术方案完全由这里的结论推出。

## 1. 结论先行

一张影楼人像是三段工作的乘积：

| 阶段 | 影楼里是谁在做 | 决定了什么 |
| --- | --- | --- |
| **拍摄前** | 灯光师、摄影师选镜头和机位 | 光的方向/软硬/光比、透视、构图、背景 |
| **拍摄中** | 摄影师测光、抓拍、选片 | 曝光、白平衡、表情与清晰度 |
| **拍摄后** | 修图师、调色师 | 肤质、局部明暗、影调与色彩 |

美图秀秀这一类 App 只接管了第三段，而且要用户自己动手：照片已经用错误的光、错误的透视、
错误的曝光拍完了，再“东补一点、西加一点”。这就是它鸡肋的根本原因——**前两段的信息在快门之后就丢了**，
而且每一步都需要用户具备修图师的判断力。

Smoothit 的方案是把三段全部搬到快门那一刻、全部自动：

1. **取景时就持续“看懂”场景**：端侧模型每帧给出 478 点 3D 人脸网格和头发/皮肤/衣服/背景分割，
   由此测出拍摄距离、头部姿态、**这张脸上实际的光照**、肤色、场景亮度。
2. **一个“导演”模块代替摄影师做决定**：曝光、白平衡、补光方向与光比、裁切构图、镜头透视校正、修图强度，
   全部按测量结果自动给出，不暴露任何滑杆。
3. **取景器显示的就是成片**：预览和成片走同一条 GPU 管线，所见即所得，按下去就是它。
4. **快门不是拍一张，而是拍一小段**：连拍几帧，自动挑睁眼、不糊、表情最好的那一帧（摄影师的“选片”）。
5. **屏幕本身当柔光箱**：暗光下界面整体变成暖白色发光面，按下快门时全屏闪光——这是真正的光子，
   不是后期提亮，还会在眼睛里留下眼神光。

事后修补式方案做不到 1、4、5，也就做不到“一键即得”。

## 2. 手机拍照的底层链路

```
场景光 ─► 镜头(焦距/光圈/距离) ─► 传感器(尺寸/量子效率/读出噪声) ─► ISP(去马赛克/降噪/多帧合成/
          │                                                          自动曝光/自动白平衡/色调映射/锐化)
          └ 透视在这里就定了                                           └ 肤色、反差、锐度在这里定 ─► JPEG/HEIF
```

每一环对自拍都不友好：

- **镜头与距离**：前置摄像头约等效 22–26 mm 广角，自拍距离 25–50 cm。影楼人像用 85–135 mm，在 1.5–3 m 外拍。
  放大率与距离成反比，所以离镜头最近的鼻子被画得偏大、耳朵和脸侧被画得偏小。
- **光**：自拍用的是“碰巧在那儿的光”——头顶灯（眼窝发黑）、背后的窗（逆光脸黑）、
  混合色温、手机屏幕的蓝光从下往上打。影楼的主光是一块大面积柔光，从斜上方 30–45° 来，辅光把光比控制在 2:1–3:1。
- **传感器**：前摄传感器小，暗光下信噪比差；ISP 用强降噪和强锐化补，结果皮肤一片“油画感”加锐化白边。
- **ISP 的取向**：手机厂商的调校目标是“所有场景都不出错”，不是“人像好看”：全局 HDR 把脸压平，
  自动白平衡对整幅画面取平均而不是对肤色负责。

## 3. 差距逐项分解

下表是整份研究的核心。“可自动弥补”一列的判断标准是：**不需要用户做任何事**。

| 环节 | 影楼怎么做 | 业余自拍的问题 | 可自动弥补？ | Smoothit 的做法 | 做不到的部分 |
| --- | --- | --- | --- | --- | --- |
| **透视** | 85 mm+，1.5 m 以外 | 近距广角，鼻大脸窄 | 部分 | 用虹膜大小测距（虹膜直径人群近似恒定 11.7 mm），按 3D 网格把脸重投影到 1.6 m 的虚拟机位 | 被遮住的部位（耳朵）无法凭空生成 |
| **机位角度** | 平视或略高 | 手机偏低：鼻孔、下颌显重 | 少量 | 检测到低机位时把头部模型绕中面部回转最多 7° | 大角度只能靠提示“手机再举高一点” |
| **光的方向与光比** | 斜上方大柔光 + 辅光，2:1–3:1 | 顶光、逆光、平光、底光 | 大部分 | 从网格法线 + 肤色亮度解出球谐光照，与目标布光相除得到逐像素补光图 | 已经投下的硬阴影（鼻影、发影）去不掉 |
| **光的量** | 灯够亮 | 暗光噪点 | 部分 | 屏幕柔光 + 快门闪光；数字提亮时自动降噪 | 屏幕亮度有限，约 30–40 cm 内有效 |
| **曝光** | 入射式测光表对着脸测 | 相机对全画面测光，逆光脸黑 | 是 | 对皮肤测光；用眼白当“灰卡”区分“深肤色曝光正常”和“浅肤色欠曝”；保护亮侧不过曝 | 源片已经过曝的高光找不回来 |
| **白平衡/肤色** | 灰卡 + 校色 | 偏黄、偏绿、偏蓝 | 大部分 | 以肤色为主、背景为辅的 MAP 估计，只去除光源偏色，保留肤色本身的深浅 | 有意的彩色氛围光不应、也不会被“纠正” |
| **皮肤质感** | 分频 + 中性灰（D&B）：留毛孔、去瑕疵、匀色 | 要么不修，要么磨成塑料 | 是 | 三频段分离：保留基底（形体与光）和细纹理（毛孔），压掉中间的瑕疵频段；颜色部分几乎全去，亮度部分只柔化 | 大面积痘印/疤痕只能减轻 |
| **五官细节** | 眼睛锐、牙白、唇色健康 | 眼无神 | 是 | 网格分区：巩膜提亮去红、虹膜加反差、牙齿去黄、唇增饱和、眼下暗沉提亮 | — |
| **景深/主体分离** | 大光圈 + 远背景 + 背景压暗 | 全景深、背景杂乱 | 大部分 | 分割 + 引导滤波抠像（发丝级），线性光下的圆盘散景，背景略压暗降饱和 | 分割出错处会有瑕疵；镂空发丝、透明物体 |
| **构图** | 眼睛在上三分线、头顶留白、视线方向留空间 | 脸居中偏下、留白失衡 | 是 | 传感器画面当作“比成片略大的底片”，自动裁出 3:4，眼线 36–43%，朝向侧留白，平滑跟随 | 只能裁小不能拉远：离得太近时会提示 |
| **时机** | 拍 200 张选 1 张 | 一按就是它，可能闭眼/手抖 | 是 | 连拍 5 帧，按睁眼（表情系数）、运动量、微笑打分选最优 | — |
| **影调与色彩** | 调色师定风格 | 手机默认的“数码味” | 是 | 亮度通道上的肩部滚降 + S 曲线、分离色调、柔光辉光、细颗粒；四种风格只改变“意图” | — |
| **解像力** | 中画幅/全画幅 | 小传感器 | 否（软件层） | 用到视频流的最高分辨率；多帧合成需要原生相机管线（见路线图） | 传感器物理极限 |

### 3.1 透视：最容易被忽略的差距

文献对“自拍效应”有定量结论：Ward 等（JAMA Facial Plastic Surgery, 2018）用针孔模型算出，
在 30 cm 处拍摄，鼻宽相对颧宽比远距离拍摄大约 30%。本仓库的单元测试用 MediaPipe 的通用人脸模型
在理想针孔相机下复现了同一量级：30 cm 相对 1.6 m，鼻翼宽/脸宽之比大约高 20%。

关键洞察是：**3D 人脸网格给了每个顶点的深度，所以可以真的做一次“推拉变焦”**——
把每个点反投影到米制空间，换成 1.6 m 的机位再投影回来，差值就是该点应有的位移，再平滑插值成一张变形网格。
测试表明，全强度时这一步能消除 75% 以上的透视形变（残差主要来自弱透视深度近似）。

一个产品上的取舍需要明说：忠实的远距离透视会让脸的**外轮廓变宽约 15%**（自拍其实是“显瘦”的）。
这在光学上正确，但没有人会觉得好看。所以默认设置只对“突出于面部正面”的部分（鼻、唇）做充分校正，
轮廓只动 12%：鼻子回到正常比例，脸不变宽。

### 3.2 光：能测量，才能纠正

皮肤接近漫反射。Ramamoorthi & Hanrahan（2001）、Basri & Jacobs（2003）证明：凸的漫反射物体在任意远场光照下的
外观，可以用 9 个球谐系数表达到 99% 左右的精度。我们手里有每个网格顶点的法线，又能量出该处皮肤的亮度，
于是可以最小二乘解出这 9 个系数——**等于测出了这张自拍实际处在什么光里**。

有了测量值，纠正就是除法：`增益 = 目标布光(法线) / 实测光照(法线)`（比值图重打光）。
目标布光是经典影楼设定：主光偏轴 35°、仰角 28°、光比 2.4:1、带包裹的大柔光。

几个让它在真实照片上站得住的工程细节：

- 只用朝向镜头的皮肤顶点拟合，并用 Huber 权重迭代，抵抗投影、高光和碎发；高阶项加岭回归（可见法线只覆盖半球）。
- 主光放在**现有光的同一侧**：增强真实光看起来自然，对着干则去不掉已有的阴影。现有光没有方向性时用“短光”（照亮远离镜头的那侧脸颊，显瘦）。
- “好光不动”：先评估实测光是否需要纠正（光比超过约 2.3:1、底光、陡峭顶光），不需要时只保留 30% 的轻微塑形。
- 补光安全、减光危险：增益上限 +0.9 档，下限只有 −0.36 档。
- 网格法线先做三轮松弛，否则鼻梁这类折线会在增益图上留下可见的接缝。

### 3.3 皮肤：分频而不是磨皮

磨皮的本质是低通滤波，毛孔和瑕疵一起没了，所以是塑料脸。修图师的做法（分频 + 中性灰）是把图像拆成频段分别处理。
Smoothit 在 GPU 上实时做同样的事：

```
原图 = 基底(掩膜双边滤波：形体、光影)  +  瑕疵频段(介于两者之间)  +  纹理(比毛孔尺度更细的一切)
输出 = 基底 + 纹理 × 1.0 + 瑕疵频段的亮度 × (1 − 0.48) + 瑕疵频段的颜色 × (1 − 0.85)
```

最后一行是这套方案和“高级磨皮”的分水岭：瑕疵频段的**颜色**成分（泛红、色斑、痘印）几乎全部去掉；
**亮度**成分只柔化一半——因为它同时承载着法令纹、颧骨、鼻翼这些面部造型，全去掉就是蜡像。
所有尺度都按瞳距自适应，远近脸的处理强度一致。

皮肤掩膜由三个互相独立的证据合成，避免任何单点失效把非皮肤磨掉：网格分区（在脸内、不在眼/唇/眉上）、
语义分割（脸部皮肤 + 身体皮肤，覆盖脖子肩膀）、颜色统计（与本人实测肤色的色度距离）。

### 3.4 曝光与白平衡：对脸负责，同时尊重肤色

对脸测光有一个经典歧义：脸暗，是肤色深还是欠曝？处理不好就会把深肤色“漂白”。
Smoothit 用眼白当参照：皮肤亮度远低于眼白 → 肤色本身深 → 目标亮度定得更低。

白平衡同理。在对数色度空间里，肤色自身的差异、光源色温、光源色调三者各有方向，且肤色差异与色温几乎平行——
只看皮肤无法完全分开。因此用带先验的 MAP 估计：给“肤色差异”宽先验、给“色温偏差”窄先验
（把深肤色或晒黑的肤色误判成暖偏色并漂白，是更严重的错误），色调（绿/品红）方向与肤色轨迹近乎垂直，可以放心校正。
色度只取皮肤较亮的一半来量，因为相机的色调曲线会在暗部夸大通道比。

## 4. 做不到的，如实说

“无需任何配合就得到红毯大片”在物理上不成立，软件能把一张 60 分的自拍稳定地拉到 85 分，但有硬边界：

- **强逆光、硬顶光已经投下的阴影**：只能补光减轻，不能消除。
- **离得太近（< 25 cm）或机位太低**：透视校正和回转都有上限。
- **极暗环境**：数字提亮会放大噪点；真正的解法是多帧合成（原生管线）或真实补光。
- **分割失败**：复杂背景、镂空发丝、与背景同色的衣服会让虚化出瑕疵，所以默认虚化量保守，暗光下再减半。
- **姿态、表情、妆发**：这是模特和化妆师的工作。

对这些情况，Smoothit 的原则是：**能修的全部默默修掉；修不了的，才给一句最短的提示**
（“手机稍微拿远一点”“背光较强，转向光源会更通透”），而且提示稳定出现 0.9 秒以上才显示，不打扰正常拍摄。

## 5. 技术路线与取舍

**为什么是端侧实时，而不是拍完上传云端用大模型重绘？**
生成式重绘可以给出更“惊艳”的结果，但它会改变人的长相（身份漂移），需要上传人脸照片，
有秒级到十秒级延迟，取景器里看不到结果。这三点分别违背了“这还是我”“隐私”“一键即得”。
Smoothit 的每一步都是对真实像素的几何与光度变换，不生成任何不存在的内容。

**为什么用 WebGL2 着色器 + MediaPipe，而不是直接写原生？**

- 目标是 iOS 和 Android 都要。同一套 GLSL ES 3.00 着色器既能在两个平台的 WebView 里跑，也能原样搬到
  Android 的 OpenGL ES 3、近乎原样搬到 Metal；478 点网格和多类分割模型两端都有同名实现。
- 整条管线可以在无头浏览器里用真实人像和假摄像头做端到端自动化测试——这份仓库里的每个环节都是这样验证出来的。
- 代价：Web 相机 API 拿不到传感器 RAW、拿不到 1200 万像素的静态拍照管线（只能用视频流分辨率）、
  曝光控制有限、不能直接调屏幕亮度。

**路线图（按对画质的贡献排序）：**

1. 原生采集插件：AVFoundation / Camera2 的全分辨率静态拍照 + 曝光/对焦锁定 + 屏幕亮度拉满。
2. 多帧合成降噪（对齐 + 时域融合），解决暗光。
3. 原生深度（TrueDepth / 双像素）替代纯分割做景深，前后景过渡更真实。
4. 多人场景：对每张脸分别做几何与光照（目前主脸完整处理，其他人靠分割得到匀肤）。
5. 可学习的小型重打光网络处理硬阴影（Sun et al. 2019 / Pandey et al. 2021 的端侧化）。

## 6. 这一版是怎么验证的

- **单元测试（30 项）**：把 MediaPipe 通用人脸模型放进理想针孔相机，合成“已知距离、已知姿态、已知光照”的输入，
  断言测距误差 < 4%、姿态符号与量级正确、透视校正消除 > 75% 形变、光照拟合抗离群点、
  重打光不改变平均曝光、好光基本不动、构图恒为 3:4 且不出画、白平衡不误伤深/浅肤色，等等。
- **视觉回归**：`scripts/visual-test.mjs` 在无头 Chromium 里把静态人像送进与成片完全相同的管线，输出前后对比。
  测试集包含专业人像（验证“好照片不被改坏”）和对其做物理合理退化得到的业余条件：
  暗光钨丝灯、逆光、荧光灯绿偏、屏幕蓝光暗场、过曝。
- **端到端**：`scripts/e2e.mjs` 用假摄像头（视频文件）启动真实 App：取景 → 自动柔光 → 快门连拍选片 → 成片 → 作品集。

**尚未验证的**：真机上的帧率与发热、各机型前摄的实际视场角（测距假设 24 mm 等效）、
iOS/Android WebView 的相机权限流程、曝光补偿接口在各浏览器的行为。这些必须在真机上跑一轮。
